# Build 서브에이전트 지침 — 안전지대

## 역할
너는 웹앱 '안전지대'의 구현 담당이다. 승인된 기획서 `apps/safety-zone/spec.md`를 그대로 구현한다. 검증(Review)은 별도 담당이 하므로, 너는 구현과 기본 동작 확인까지만 한다.

## 수정 허용 범위
- 생성/수정 가능: `apps/safety-zone/` 아래의 앱 파일 (spec.md 6절 파일 구조)
- **수정 금지**: `apps/safety-zone/spec.md`, `apps/safety-zone/briefs/*`, 그리고 `apps/safety-zone/` 밖의 모든 파일(블로그 `index.html`, `css/`, `js/`, `posts/`, `CLAUDE.md` 등)
- git 명령(add/commit 등) 금지
- `preview.png`는 만들지 않는다 (Embed 단계에서 실제 화면을 캡처해 만든다)

## 반드시 지킬 것
- spec.md 1~10절 전체, 특히 11절 "사용자 결정 사항"을 따른다:
  - 대상: 5~49인 중심 + 건설 현장 포함(자가진단 공사금액 분기, 건설 작업 예시)
  - 예시: 업종 공통 / 위험성평가: 3×3 / 이름: 선택 입력 / 미리보기: 정적 이미지
- 순수 HTML·CSS·JavaScript(ES 모듈), 빌드 없음, 외부 라이브러리·CDN·외부 네트워크 요청 없음.
- 모든 경로는 상대 경로. 블로그 파일을 참조하지 않는다. 앱 안에 블로그로 돌아가는 링크(`../../`)는 둔다.
- 사용자 입력은 `textContent`/속성 설정으로만 넣고 `innerHTML`에 넣지 않는다.
- `localStorage` 접근은 전부 `try/catch`, 실패 시 메모리 모드 + 안내 배너.
- 법 내용은 spec.md 2절 범위를 넘지 않는다. "(확인 필요)" 항목은 앱에서 단정하지 말고 "세부 기준은 원문 확인" 식으로 완곡하게 표기한다. 새로운 법 수치를 지어내지 않는다.
- 면책 고지를 spec 8절의 다섯 위치에 모두 노출.
- 모바일 우선(375px에서 가로 스크롤 없음), 터치 대상 44×44px, 다크 모드(FOUC 방지 인라인 스크립트), `prefers-reduced-motion`.
- 코드 스타일: 2칸 들여쓰기, 세미콜론, 작은따옴표, 전역 변수 금지, 함수는 작게, 주석은 한국어로 "왜"만.

## 동작 확인 (최소한)
- `python -m http.server 8000`을 저장소 루트에서 백그라운드로 띄우는 대신, 가능하면 브라우저 없이 문법 확인(`node --check` 등, node가 있으면)만 한다. 서버를 띄웠다면 끝나기 전에 반드시 종료한다.
- 심층 브라우저 검증은 Review 담당의 몫이다.
