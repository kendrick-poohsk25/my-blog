# Review 지침 — 공통 색상 토큰 분리와 사용법 안내 검증

Build 지침은 `apps/safety-zone/briefs/tokens.md`에 있다. 그 결과를 검증한다.

## 수정 허용 범위
- `apps/safety-zone/review.md`에 "4차 검증 — 공통 색상 토큰·사용법 안내" 섹션을 **추가**하는 것만 허용한다.
- 코드 파일은 고치지 않는다. 문제는 기록만 한다. git 명령 금지.

## 확인 방법
- 블로그 서버가 http://localhost:8123/ 에서 이미 실행 중이다(이 폴더를 서빙). 새 서버를 띄우지 않는다.
- 브라우저 확인은 headless Edge로 한다.
  - 예: `"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless=new --user-data-dir=<임시폴더> --window-size=...`
  - `--screenshot`으로 화면을 캡처하거나, `--dump-dom`으로 DOM을 확인한다.
  - 계산된 스타일은 `--remote-debugging-port` + node 스크립트로 확인해도 된다.
- 임시 파일은 프로젝트 밖 임시 폴더에 둔다.

## 확인 항목
1. **블로그 회귀**
   - `css/tokens.css`의 값이 이전 `css/style.css`의 값과 같은지 확인한다. `git show HEAD:css/style.css`와 대조한다(읽기 전용 git은 허용).
   - 블로그 메인의 라이트·다크 화면이 정상인지 본다. 글 상세 화면도 확인한다.
   - 콘솔 오류가 없는지, tokens.css가 404가 아닌지 확인한다.
2. **앱 색상**
   - `/apps/safety-zone/`에서 강조색이 블로그 파랑(라이트 #1f5bd8, 다크 #7cafff)인지 계산된 값으로 확인한다.
   - 초록 강조색이 남아 있지 않은지 확인한다. 완료 상태색 `--ok`는 초록이 맞다.
   - 버튼, 탭 바, 배지, 선택된 선택지, card-accent의 대비가 4.5:1 이상인지 확인한다.
3. **테마 공유**
   - 블로그에서 다크로 바꾼 뒤 앱을 열면 다크로 보이는지 확인한다(앱 설정이 system일 때).
   - 앱에서 토글한 뒤 블로그를 열면 같은 테마인지 확인한다.
   - 앱 더보기에서 '기기 설정 따르기'를 고르면 블로그 `theme` 키가 지워지는지 확인한다.
   - 저장소를 쓸 수 없을 때 오류 없이 동작하는지 코드로 확인한다.
4. **사용법 안내**
   - 홈 '사용법' 카드가 진단 전에는 펼쳐지고 진단 후에는 접히는지 확인한다.
   - 5단계 링크가 올바른 경로로 가는지, 높이가 44px 이상인지 확인한다.
   - 더보기에도 같은 내용이 나오는지, 문구가 `js/data/guide.js` 한 곳에서만 정의되는지 확인한다.
5. **모바일**
   - 375px 폭에서 홈·더보기에 가로 스크롤이 없는지 확인한다.
6. **인쇄 CSS**
   - print.css 값이 파랑으로 바뀌었는지 확인한다(코드 확인).
7. **코드**
   - 수정 파일 `node --check`
   - 쓰이지 않는 변수가 남았는지, 정의되지 않은 변수를 참조하는 곳이 있는지 확인한다(`var(--x)` 전체 대조).

## 보고
review.md 섹션에 항목별 통과/문제를 적는다. 문제는 심각도(높음/중간/낮음), 파일:줄, 재현 방법과 함께 적는다. 확인하지 못한 항목은 이유를 적는다. 마지막 응답에서 같은 요약을 한국어로 돌려준다.
