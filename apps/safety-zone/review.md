## 발견한 문제

### 중간

**M1. 브라우저 메뉴(Ctrl+P)로 인쇄하면 빈 페이지**
- 위치: `css/print.css:23-25`, `js/utils/export.js:47-58`
- 재현: 아무 화면에서나 Ctrl+P → 미리보기가 비어 있음. 앱 본문은 모두 `display:none`이고, `#print-area`는 '인쇄' 버튼을 누를 때만 채워짐
- 영향: 증빙을 남기려고 흔히 쓰는 방법인데 결과물이 빈 종이라서, 사용자가 기록이 없다고 오해할 수 있음
- 수정 제안: 버튼으로 인쇄할 때만 앱을 숨기도록 범위를 좁힘. 예를 들어 `printReport`에서 `document.body.classList.add('printing-report')`를 하고 `afterprint`에서 빼거나 `#print-area`를 비움. print.css는 `body.printing-report > *:not(#print-area)`만 숨김. 그 밖의 경우에는 현재 화면을 인쇄하되 탭 바·헤더 버튼만 숨기는 기본 규칙을 둠

### 낮음

**L1. 전담 조직 자동 '해당 없음'이 다시 진단해도 풀리지 않음**
- 위치: `js/views/check.js:76-84`
- 재현: 20인으로 진단(org → na, 자동 메모) → 50인 이상으로 다시 진단 → org는 그대로 na
- 수정 제안: 메모가 자동 문구 그대로이고 status가 na이면 `workers >= 50`일 때 todo로 되돌림. 아니면 결과 화면에 "체크리스트에서 확인하세요" 안내를 넣음

**L2. 44px에 못 미치는 터치 대상**
- 위치: `js/views/home.js:22`('진단 결과 보기'·'다시 진단', 18px 높이), `home.js:52`('보기·수정', 21px), `js/views/log.js:96` 칩 삭제 버튼(44×40)
- 수정 제안: 홈의 글 속 링크를 `btn-ghost`/`btn-row`로 바꾸거나 `min-height:44px; display:inline-flex`를 적용. `.chip-remove`는 높이를 44px로

**L3. 일부 키만 든 백업을 가져오면 나머지 데이터와 면책 동의가 초기화됨**
- 위치: `js/store.js:255-267`
- 재현: `data`에 `logs`만 있는 백업을 가져옴 → profile·duties·risks가 비고 `meta.disclaimerAcceptedAt`이 null이 되어 새로고침하면 모달이 다시 뜸
- 수정 제안: `restoreBackup`에서 `data`에 없는 키는 건너뜀(`parseBackup`이 원래 있던 키 목록을 함께 넘기도록). 적어도 meta는 현재 값을 유지

**L4. 내보내기 종료일 기본값(오늘) 때문에 미래 날짜 기록이 빠짐**
- 위치: `js/views/more.js:105`
- 재현: `#/log/2030-01-01`처럼 미래 날짜 기록은 만들 수 있지만, 기본 설정으로 내보내면 빠짐
- 수정 제안: 종료일 기본값을 비워 두거나("오늘까지" 문구로 대신) 기록 날짜를 오늘 이하로 제한

**L5. 체크리스트 CSV·인쇄의 "다음 점검 예정일" 칸에 '해당 없음'이 나옴**
- 위치: `js/views/more.js:28`
- 반기 주기가 없는 항목도 '해당 없음'으로 표시되어, 상태 열의 '해당 없음'(na)과 헷갈림
- 수정 제안: `'-'` 또는 `'주기 없음'`으로 표시

**L6. 위험성평가 제목·평가일을 고쳐도 부제 줄과 탭 제목이 그대로임**
- 위치: `js/views/risk.js:242-245, 295`
- h1만 바뀌고 `assessedAt · 구분` 줄과 `document.title`은 다시 들어와야 바뀜
- 수정 제안: 저장 콜백에서 함께 갱신

**L7. (미확인) 면책 모달 Esc 처리**
- 위치: `js/main.js:84`
- 최신 Chromium은 `cancel`을 `preventDefault`해도 사용자 동작 없이 Esc를 연달아 누르면 닫힐 수 있음. 닫혀도 동의 기록이 남지 않아 다음 방문에 다시 뜨므로 영향은 작음. 실제 동작은 확인하지 못함
